## Остаточный долг

### Невнятная ошибка при извлечении аудио из видео без звука
Если в файле нет звуковой дорожки, операция падает, и в очередь попадает сырой
вывод ffmpeg, ещё и обрезанный с начала (`truncate` берёт хвост строки):

```
ffmpeg extract: ffmpeg copy: exit status 234: ideoHandler
  vendor_id : [0][0][0][0]
Output file does not contain any stream
```

Поведение верное — пустой файл создавать не нужно, — но пользователю следует
показывать «в файле нет аудиодорожки». Правка в `audio.Extract`: распознавать
`does not contain any stream` и возвращать понятную ошибку. Пункт меню
«Извлечь аудио» при этом показывается у любого видео: заранее наличие звука
не проверяется.


### Тестовое покрытие HTTP-обработчиков
Появились первые тесты самого пакета `handler` — на безопасную отдачу файлов.
Остальное (разбор запросов, коды ответов, набор событий `HX-Trigger`)
проверяется по-прежнему косвенно. Приоритетное к покрытию:
- коды ответов на несуществующий id: сейчас там 500 с текстом ошибки СУБД
  вместо 404, и отличить «не нашли» от «база упала» нельзя;
- ограничение размера тела JSON-запросов (его нет);
- негативный тест списка публичных путей: обход не удаётся, но держится это на
  нормализации в `ServeMux`, а не на собственной проверке.

### Браузерные тесты гоняются вручную
`go test ./tests/e2e/...` пропускается, если браузер не найден, и запускается
отдельным job в CI. На машине разработчика Chrome нет, поэтому локально их
приходится гонять в контейнере:

```bash
docker run --rm -v "$PWD":/src -w /src -v "$HOME/go/pkg/mod":/go/pkg/mod \
  -e CHROME_PATH=/usr/bin/chromium-browser golang:1.26-alpine \
  sh -c "apk add --no-cache chromium && go test ./tests/e2e/..."
```

Стоит завернуть это в `make e2e` или `docker compose -f compose.test.yml`.

### Плейлист и облако тегов при постраничной выдаче
Очередь воспроизведения теперь всегда берётся с сервера, но облако тегов
по-прежнему показывает первые пять тегов с кнопкой «ещё N», которая просто
раскрывает уже загруженное. При большом числе тегов список неполон.

### Токены постоянных ссылок без срока жизни
Ссылку можно отозвать вручную, но автоматического истечения нет. Для домашнего
сервиса приемлемо; при желании — поле `expires_at` и проверка в `ResolveToken`.

## Сделано

### Фронтенд
- **ES-модули.** `app.js` на 880 строк разобран на десять модулей
  (`main`, `actions`, `api`, `toast`, `filters`, `player`, `selection`,
  `collections`, `library`, `menu`). Сборщик не нужен — браузер грузит модули сам.
- **Делегирование событий.** Inline-обработчиков в шаблонах не осталось:
  разметка объявляет `data-action`, модули регистрируют обработчики, единый
  слушатель на `document` переживает подмену фрагментов HTMX.
- **Защита от рассинхрона.** Тест в `web/templates` рендерит все компоненты и
  сверяет использованные действия с зарегистрированными в JS; отдельный тест
  запрещает inline-обработчики. В браузере то же делает `auditActions()`.
- **CSS вынесен** из `layout.templ` (600 строк) в `web/static/app.css`;
  инлайновые стили заменены классами, шаблон ужался до 30 строк.

### Архитектура
- **Слой сервисов** — [library.Service](internal/library/service.go) и
  [queue.Service](internal/queue/service.go); HTTP и Telegram стали адаптерами.
- **Единый источник настроек** — [settings.Provider](internal/settings/provider.go).
- **Полосы фоновых операций** — light/heavy, таймаут, отмена, восстановление
  после рестарта, уборка по сроку хранения.
- **Read-модель медиатеки** — один построитель запросов вместо пяти копий.
- **Разделение пулов БД** — писатель + пул читателей. Заодно выяснилось, что DSN
  был написан в синтаксисе `mattn/go-sqlite3`, который `modernc` игнорирует:
  WAL, `busy_timeout` и внешние ключи не применялись вовсе.
- **Типизированные SSE-события** — темы `library`/`queue`/`tags`/`collections`
  со склейкой публикаций в окне 300 мс.
- **Интерфейсы на границах** — `Downloader` и `Clock` в пуле загрузок,
  `messenger` в боте: backoff, отмена и сценарии бота проверяются без сети.
